# list: 노드를 연결

위치를 알고 있을 때 삽입·삭제에 유리합니다. 인덱스 []는 제공하지 않으며 위치 탐색에는 순회가 필요합니다.

## 개념과 동작 원리

list는 양방향으로 연결한 노드들로 원소를 저장합니다. 주어진 위치의 삽입·삭제는 빠르지만 해당 위치를 찾으려면 보통 순회가 필요합니다.

## 사용 시점과 다른 개념의 구분

원소 위치를 반복자로 유지하며 중간 삽입·삭제가 많은 경우에 비교합니다. vector처럼 연속 저장·인덱스 접근을 제공하지 않습니다.

## 문법과 예제

```cpp
std::list<int> values{10, 20};
values.push_front(5);
std::cout << values.front();
```

**결과:** 5. 빈 컨테이너에서 front·back·pop_back 등의 원소 접근·삭제는 피합니다.

## 예제를 이해하는 순서

push_front(5)로 앞 노드를 추가해 front가 5가 됩니다. 순회는 연결된 노드를 따라가며 []로 임의 위치를 직접 찾을 수 없습니다.

## 이해 확인

**질문:** list가 모든 경우 vector보다 빠른가?

**답:** 아닙니다. 위치 탐색·추가 메모리·연속 저장의 순회 효율을 함께 비교해야 합니다.
