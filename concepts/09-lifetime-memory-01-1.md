# 객체 수명

객체가 생성되어 존재하다가 소멸할 때까지의 기간입니다. 스코프는 이름 사용 범위이므로 수명과 구분합니다.

## 개념과 동작 원리

수명은 객체가 초기화되어 유효하게 존재하는 기간입니다. 일반 자동 지역 객체는 블록 종료 때 소멸하고 동적 객체는 대응하는 소멸·해제 동작까지 존재합니다.

## 사용 시점과 다른 개념의 구분

주소·참조를 저장하거나 반환할 때 원본이 언제 사라지는지 추적합니다. 스코프는 이름 범위, 수명은 객체의 존재 기간이라는 점을 구분합니다.

## 문법과 예제

```cpp
{ int hp = 100; std::cout << hp; }
```

**결과:** 100. 블록이 끝나면 hp의 수명이 끝납니다. 수명이 끝난 객체의 포인터·참조는 사용하지 않습니다.

## 예제를 이해하는 순서

블록 안의 hp는 그 블록 안에서 사용할 수 있습니다. 주소를 바깥에 저장해도 블록 종료 후 hp의 수명을 계속 유지시키지는 못합니다.

## 저장 기간과 수명 비교

| 구분 | 전형적인 생성·종료 | 수명 관리 | 주의 |
| --- | --- | --- | --- |
| 일반 자동 지역 객체 | 블록 실행 중 생성, 블록 종료 시 소멸 | 범위에 연결 | 주소를 밖으로 넘겨도 수명은 늘지 않음 |
| static 지역 객체 | 초기화 지점 도달 후 초기화, 정상 종료 과정에서 소멸 | 정적 저장 기간 | 이름은 해당 블록에서만 사용 |
| 동적 객체 | new로 생성, delete로 소멸·해제 | 소유자가 책임 | raw 포인터 지역 변수가 사라져도 대상은 남음 |
| RAII 소유 객체 | 자신의 수명에 자원 획득·정리를 연결 | 소멸자로 자동 정리 | 복사·이동 정책까지 소유권과 일치해야 함 |

## 이해 확인

**질문:** 포인터를 보관하면 대상 수명이 늘어나는가?

**답:** raw 포인터만 보관해서는 늘어나지 않습니다. 소유권과 대상 수명을 별도로 관리해야 합니다.
