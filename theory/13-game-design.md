## 게임 루프: 입력·갱신·출력

한 회차마다 입력을 읽고 상태를 바꾼 뒤 현재 상태를 표시합니다. 아래는 흐름을 보여 주는 문법 틀입니다.

```text
초기화
반복하는 동안:
    입력: 사용자 의도 읽기
    갱신: 이동·충돌·승패 처리
    출력: 현재 상태 표시
자원 정리
```

**주의:** 콘솔의 입력 대기와 실시간 게임의 프레임 갱신은 다릅니다. 프로젝트에 맞춰 입력 처리 방식을 정합니다.

## 역할 분리

| 역할 | 책임 | 예 |
| --- | --- | --- |
| 보드 | 칸·좌표·보드 판정 | 빙고, 틱택토 |
| 플레이어 | 개인 상태·행동 | 체력, 이동, 선택 |
| 게임 관리자 | 시작·반복·종료 조율 | 게임 루프 |
| 씬 | 화면별 동작 제공 | 로비, 게임, 전투 |

**핵심:** 한 객체에 입력·규칙·화면·메모리 관리가 모두 몰리지 않도록 역할을 나눕니다.

## 씬 전환과 다형성

기존 씬 Exit, 현재 씬 변경, 새 씬 Enter 순서로 전환합니다. 여러 씬은 공통 Update·Draw 인터페이스로 실행합니다.

```cpp
class Scene { // main 밖: 공통 계약
public:
    virtual ~Scene() = default;
    virtual void Update() = 0;
    virtual void Draw() = 0;
};
```

**결과:** Scene 자체는 추상 클래스. 파생 씬이 Update와 Draw를 구현해야 구체 객체를 만들 수 있습니다.

## 싱글톤과 파일 분리

- **싱글톤:** 하나의 인스턴스 제공. 전역 의존이 커질 수 있어 제한적으로 사용합니다.
- **헤더 .h:** 선언과 필요한 정의. **소스 .cpp:** 구현 분리.
- **전방 선언:** 타입 이름만 먼저 알림. 객체 멤버 사용 등에는 완전한 정의가 필요합니다.

**적용:** 빙고는 보드·유저 역할 분리, 스네이크는 좌표·몸통·충돌, TextRPG는 씬 전환과 공통 인터페이스를 연결하는 실습입니다.
