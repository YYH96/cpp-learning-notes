# 추상화

필요한 역할을 드러내고 세부 구현은 감춥니다. 사용자는 객체가 어떻게 저장하는지보다 어떤 동작을 제공하는지에 집중합니다.

## 개념과 동작 원리

추상화는 사용자가 필요한 역할과 규칙을 드러내고 세부 구현 의존을 줄이는 설계 방식입니다. 인터페이스를 유지하면 내부 구현을 바꾸기 쉬워집니다.

## 사용 시점과 다른 개념의 구분

보드 판정·씬 갱신·입력 처리의 내부 과정을 호출자에게 모두 노출하지 않을 때 사용합니다. 추상 클래스는 이를 표현하는 도구 중 하나입니다.

## 문법과 예제

**예:** 게임 관리자는 보드의 CheckWin()만 호출하고 판정의 내부 반복문은 보드에 맡깁니다.

**주의:** 추상화는 설계 개념이며, 반드시 추상 클래스를 사용해야 하는 것은 아닙니다.

## 예제를 이해하는 순서

게임 관리자는 CheckWin의 결과만 필요하며 각 줄을 어떤 순서로 검사하는지 알 필요가 없습니다. 판정 구현을 바꿔도 호출 계약을 유지할 수 있습니다.

## 판정 인터페이스로 구현 숨기기

```cpp
#include <iostream>
class Board {
    int matchedCells;
public:
    explicit Board(int value) : matchedCells(value) {}
    bool CheckWin() const { return matchedCells == 3; }
};
int main() {
    Board board(3);
    std::cout << (board.CheckWin() ? "Win" : "Continue");
}
```

**결과:** Win. 실제 보드의 전체 판정 알고리즘이 아니라 인터페이스 역할을 보여 주는 최소 예제입니다. 호출자는 내부 저장 방식 대신 CheckWin이라는 계약을 사용합니다.

## 이해 확인

**질문:** 추상화는 코드를 무조건 짧게 만드는가?

**답:** 핵심은 길이보다 역할과 계약을 분리하는 것입니다. 이름만 감추고 규칙을 불명확하게 만들면 좋지 않습니다.
