# 캡슐화와 정보 은닉

캡슐화는 데이터와 동작을 묶는 것, 정보 은닉은 내부 접근을 제한하는 것입니다.

## 개념과 동작 원리

캡슐화는 관련 데이터와 동작을 한 단위로 묶고, 정보 은닉은 내부 표현과 변경 방법을 제한합니다. 목적은 객체가 지켜야 하는 유효 상태를 유지하는 것입니다.

## 사용 시점과 다른 개념의 구분

체력 0 이상 같은 규칙을 여러 코드에서 반복 검사하지 않도록 타입 안에 모읍니다. 모든 멤버의 무조건 공개 Setter는 규칙 보호를 약하게 할 수 있습니다.

## 문법과 예제

```cpp
class Player { // main 밖
    int hp = 100;
public:
    void Damage(int amount) {
        if (amount > 0) hp = amount < hp ? hp - amount : 0;
    }
    int GetHp() const { return hp; }
};
```

**예:** Damage(120) 뒤 GetHp()는 0. Getter는 조회, Setter는 검증된 변경을 맡습니다. const 멤버 함수는 조회에 사용합니다.

## 예제를 이해하는 순서

Damage는 양수 피해만 적용하고 체력이 0 아래로 내려가지 않게 합니다. 호출자는 내부 체력 표현 대신 동작 인터페이스를 사용합니다.

## 이해 확인

**질문:** private만 붙이면 캡슐화가 완성되는가?

**답:** 아닙니다. 공개 함수가 유효하지 않은 상태를 만들 수 있다면 내부 규칙도 함께 설계해야 합니다.
