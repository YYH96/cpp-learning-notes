# vector: 인덱스로 접근

연속 저장하는 가변 배열입니다. 인덱스 접근은 빠르지만 중간 삽입·삭제에는 뒤 원소 이동이 필요합니다.

## 개념과 동작 원리

vector는 원소를 연속 저장하는 가변 크기 컨테이너입니다. 인덱스 접근은 일정 시간이고, 중간 삽입·삭제는 뒤 원소 이동이 필요할 수 있습니다.

## 사용 시점과 다른 개념의 구분

크기가 달라지는 목록·보드 평탄 저장·빠른 순회에 사용합니다. 끝 추가는 재할당을 포함해 평균적인 누적 비용 관점에서 효율적입니다.

## 문법과 예제

```cpp
std::vector<int> values{10, 20};
values.push_back(30);
std::cout << values[1] << ' ' << values.size();
```

**결과:** 20 3. []는 범위를 검사하지 않습니다. at()은 범위를 검사하고 범위 밖이면 예외를 발생시킵니다.

## 예제를 이해하는 순서

push_back으로 실제 원소 수가 2에서 3이 됩니다. values[1]은 두 번째 값 20이며 at은 범위를 검사하고 []는 검사 보장이 없습니다.

## vector와 list의 선택 기준

| 기준 | vector | list |
| --- | --- | --- |
| 저장 구조 | 연속된 원소 | 연결된 노드 |
| 위치 접근 | 인덱스 O(1) | 해당 위치 탐색 O(n) |
| 중간 삽입·삭제 | 뒤 원소 이동, 일반적으로 O(n) | 위치를 이미 알면 O(1) |
| 순회 | 연속 저장의 효율 활용 | 연결 노드를 따라 이동 |
| 주소·반복자 | 재할당·삭제 위치에 따라 무효화 | 일반 삽입은 기존 원소 유지, 삭제한 원소는 무효화 |

**복잡도 읽기:** O(1)은 원소 수에 비례해 단계가 늘지 않는다는 뜻, O(n)은 원소 수에 비례할 수 있다는 뜻입니다. list의 삽입 위치를 찾는 시간은 별도로 계산합니다.

## 이해 확인

**질문:** push_back 후 이전 원소의 주소는 항상 유효한가?

**답:** 재할당이 발생하면 무효화됩니다. 주소·참조·반복자를 저장한 코드는 용량 변화도 확인해야 합니다.
