복습할 때 바로잡아야 할 부분

한눈에 보는 핵심

복습에서는 문법이 맞는 것과 동작이 올바른 것을 구분하고, 경계 조건부터 확인합니다.

01

경계 조건

빈 컨테이너, 마지막 인덱스, 검색 실패를 확인합니다.

02

수명 확인

객체가 살아 있는지, 해제 주체가 누구인지 추적합니다.

03

완성도 구분

작성 중인 실습 코드와 검증한 복습 예제를 구분합니다.

개념 비교

상황먼저 확인잘못 사용하면
빈 vectorempty()back·pop_back의 전제 위반
문자열 검색 실패npos 여부위치를 잘못 사용
동적 객체 해제소유권·가상 소멸자누수·정의되지 않은 동작
자주 헷갈리는 점

컴파일 성공은 로직의 정확성을 보장하지 않습니다. 정상 입력·경계 입력·실패 입력을 나누어 결과를 확인합니다.

상세 설명과 예제 펼치기필요한 내용만 골라 읽기+

수업 자료는 작성 중인 예제도 포함하므로 아래 항목을 정확히 구분합니다. 원문 코드는 하위 페이지에 그대로 남기고 본문에서는 올바른 규칙으로 설명했습니다.

  • string 길이에는 공백이 포함되고, substr·replace의 두 번째 인자는 개수입니다.
  • vector의 reserve와 resize는 다릅니다. clear는 capacity를 줄이지 않으며 빈 컨테이너의 pop_back은 피해야 합니다.
  • 부모의 함수가 virtual이 아니면 부모 포인터를 통한 호출이 자식 함수로 자동 연결되지 않습니다.
  • 동적 객체는 생성한 주체가 해제를 책임져야 합니다. 컨테이너에서 포인터를 없애는 것과 객체를 delete하는 것은 다릅니다.
  • find·숫자 야구·상속 계층 실습에는 작성해야 할 부분이 남아 있습니다. 안내만 있는 파일을 완성 코드로 보지 않습니다.
  • TextRPG는 씬 구조와 로비에서 게임 씬으로 넘어가는 단계이며 전투·탐색·상점 전체 구현이 완료된 상태가 아닙니다.
  • 스택·큐·맵·set은 자료구조 목록으로 소개된 수준입니다. 이 노트는 실제 구현 예제가 있는 vector·list에 중심을 둡니다.
